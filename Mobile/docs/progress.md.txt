### Bug — BottomNavigationView Home Tab Unresponsive

**Status:** ✅ Fixed 2026-06-01 — `MainActivity.java` replaced `NavigationUI.setupWithNavController`.

#### Observed symptom

After implementing P1 #1 and P1 #2, the Home tab in `BottomNavigationView` did not
respond to taps from any screen. Icon did not become selected. No navigation occurred.
No crash. Products / Cart / Account tabs worked normally.

#### Confirmed root cause (Logcat evidence)

Diagnostic log confirmed:
- `OnItemSelectedListener` DOES fire for the Home tab (touch reaches the listener ✓)
- `NavigationUI.onNavDestinationSelected` returns `false` for Home tab on every tap
- `onNavDestinationSelected` returns `true` for Products/Cart/Account tabs ✓

Logcat excerpt:
```
CLICK: itemId=2131230971 homeId=2131230971 match=true
onNavDestinationSelected returned: false   ← always false for Home
```

`onNavDestinationSelected` returns `false` only when `NavController.navigate()` throws
`IllegalArgumentException` internally. In Navigation Component 2.7.6,
`NavigationUI.setupWithNavController` automatically adds `saveState=true` and
`restoreState=true` to all bottom nav navigate calls. For the Home tab, the navigate
destination (`homeFragment`) equals the `popUpTo` target (`graph.startDestination =
homeFragment`). This combination causes Navigation 2.7.6 to throw
`IllegalArgumentException` — saving and immediately restoring the same key creates an
internal conflict. The exception is caught silently; `false` is returned; BottomNavigation
does not select Home; no navigation occurs.

This does not affect Products/Cart/Account because their destination IDs differ from the
`popUpTo` target (`homeFragment`).

This bug predates P1 #1 and P1 #2. P1 #2's Collections section made the non-Home
navigation paths prominent, which is when the bug was first noticed during testing.

#### Fix applied

`MainActivity.java` — replaced `NavigationUI.setupWithNavController` with:
- Manual `setOnItemSelectedListener` using plain `NavOptions` (no `saveState`/`restoreState`)
- Manual `addOnDestinationChangedListener` to update tab visual state on destination change

No nav_graph, fragment, adapter, or layout changes.

### P2 #7 — Search: Real-time Debounce + Suggestions

- `EditText` pill-shape (bo tròn) bên dưới toolbar, `focusableInTouchMode="true"` để nhận input đúng

- `SearchView` (có sẵn) thêm `onQueryTextChange` với 300ms debounce
- Gọi `viewModel.searchForSuggestions(query)` → API `GET /products?q=query&limit=8`
- Suggestions overlay lên content bên dưới (FrameLayout wrapper + `elevation="8dp"`)
- Tap suggestion → navigate thẳng vào **ProductDetail**

`allProducts`, reset `page=1`.
